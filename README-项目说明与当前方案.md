# 项目说明：三个月求职导向学习与项目实践计划（总体职业规划根目录）

最后更新：2026-09-19

## 一、这个文件夹是做什么的

这是一个总体职业规划的根目录。用户收集了腾讯、字节跳动、米哈游、拼多多共18个感兴趣的技术岗位，目的是：**在接下来三个月里，根据这些岗位的真实要求学习、做项目实践，积累可以写进简历、讲给面试官听的具体证据，最终用于投递求职。**

本仓库是这个计划的**计划层**，不含项目代码；六个项目各有独立的 GitHub 仓库（见下方"确定方案"）。所有学习和项目方向都必须能追溯到本仓库里岗位原文的具体要求，不凭空堆砌技术栈，也不夸大项目能覆盖的岗位要求程度。

## 二、本仓库文件说明

- `岗位.txt`：18个岗位链接清单（原始13个链接加上补充的5个拼多多链接）（腾讯4、字节4、米哈游5、拼多多5）。
- `岗位要求原文.md`：18个岗位的官方职责/要求/加分项原文整理（已按用户要求移除工作年限）。**任何项目方向的判断都应以此文件为准，不要凭空补充JD未写的内容。**
- `岗位分析.md`：对18个岗位的分类、逐岗位解读、同类岗位共性对比、四家公司特点归纳，以及六项目并行方案与岗位能力映射。**这是所有决策的分析基础。**
- `README-项目说明与当前方案.md`（本文件）：项目总入口说明，记录确定下来的方案，供接续这个项目的Agent或用户本人快速理解全局。
- `环境与踩坑记录.md`：三台机器（Mac / tx / luowindows）的实际环境、三种不同的代理机制、以及已经踩过的坑。**动环境之前必读**，它不属于上面那条岗位依据链，是操作层记录。
- `AGENTS.md`：给编码 agent 的指引（Claude Code 读同目录的 `CLAUDE.md`，两者都指向 `AGENTS.md`，正文只维护一份）。
- `scripts/bootstrap-workspace.sh` / `.ps1`：在新机器上一条命令拉齐七个仓库。
- `scripts/run-on-tx.sh`：在 tx 上跑命令前强制同步代码并校验哈希，避免"测试通过但测的是旧代码"。
- 各项目的技术方案、进度记录写在**各自的仓库**里（`docs/progress.md`、`docs/design-decisions.md`），不集中到这里；排期写在 `总节奏表.md`，汇总看板写在 `进度总览.md`（尚未创建）。

### 已确定的决策（2026-09-19）

- **岗位 08**（字节 AI 全栈-客服平台）此前未分配，现**挂到 ③ 下作为子方向**，不新增第七个项目。但 08 的 JD 含全栈/前端要求而 ③ 不做前端，这部分**不声称覆盖**。
- **② 使用 Unity `2022.3.38f1c1`**（LTS）。建工程后再换版本代价很大。
- **① 使用 UE `5.6` + Visual Studio Community 2022**（VS 装在 `F:\VS\IDE`，17.14 正是 UE 5.6 的推荐配对，且是唯一装了 C++ 游戏开发工作负载的实例）。UE 尚未安装，待用户下载。
- **分工模式**：③⑥ 偏产出（Claude 主写，用户做设计决策）、⑤ 偏学习（Claude 写脚手架，核心算法留给用户实现）、①② 混合（Claude 写代码，用户在编辑器操作）。
- **每周投入 10–15 小时**，13 周约 130–195 小时，采用主力档轮转（每周 1–2 个项目为主力，其余维持档）。
- **第一周主力：④ `agent-memory`。**
- **需要 Docker 时默认跑在 tx 服务器上**，在 Mac/Windows 起容器前须征得用户同意。

**不纳入范围**：18（前端方向），用户明确不需要。

**关于⑤和⑥**：范围和深度按三个月节奏推进，不因为"时间可能不够"而跳过或缩水规划——持续产出学习内容和项目进展即可，用户如果实际时间不够会自行取舍，不需要提前在方案里预设降级或砍掉。

## 六、给后续Agent的提示

- 关于"岗位要求"的判断，以 `岗位要求原文.md` 为基础依据；如需要补充某类岗位可能涉及的其他技术要求（比如某个技术方向在同类岗位中通常还会考察什么），可以通过网络搜索等方式补充，但要明确区分"JD原文明确写的"和"补充推断/行业常见要求"，不要把补充内容混淆成JD本身的硬性条件。
- 用户明确要求学习计划和项目设计不夸大、不虚构完成度或规模（比如不能把本地测试数据包装成生产级用户量，不能把加分项写成硬性门槛），沟通和产出时延续这个原则。
- ⑤和⑥两条线（02、06/13/15/16/17）需要持续推进和产出，即使用户当下没有时间逐条查看确认，也应按既定方向继续做，不要因为缺少即时反馈就搁置。
- 6个项目彼此独立，但③和④是调用关系（③依赖④），后续拆解周计划或技术方案时注意保持这个依赖关系清晰。
- **AI 产出的代码不等于可以写进简历。** 用户要能在面试里讲清每个关键设计取舍，偏产出的项目要同步维护 `docs/design-decisions.md`。
- **记录去哪儿**：仓库指引进该仓库 `AGENTS.md`（不要写进 `CLAUDE.md`，那只是指路）；环境与工具链的坑进 `环境与踩坑记录.md`；已发生的进展进各仓库 `docs/progress.md`；设计取舍进 `docs/design-decisions.md`；排期进 `总节奏表.md`。
- **多机协作**：三台机器（Mac / tx / luowindows），GitHub 是唯一事实源，开工 `git pull`、收工 `git push`，同一项目同一时间只在一台机器上改。细节见 `环境与踩坑记录.md`。
